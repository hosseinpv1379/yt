# ربات تجاری تلگرام برای زیرنویس و دوبله فارسی یوتیوب

ربات عمومی لینک یوتیوب را می‌گیرد، نوع خروجی و کیفیت را می‌پرسد و هزینهٔ دقیقه‌ای را از کیف پول تومانی کم می‌کند. شارژ با کارت‌به‌کارت و بررسی دستی رسید انجام می‌شود؛ مدیر هم می‌تواند مستقیماً کاربران را شارژ یا از موجودی‌شان کم کند. نرخ‌ها از پنل `/admin` قابل تغییرند. job ناموفق یا نیمه‌تمام پس از restart به کیف پول برمی‌گردد. پیشرفت با پیام زنده و قابل‌ویرایش تلگرام نشان داده می‌شود. در حالت زیرنویس و بدون واترمارک، ویدیو re-encode نمی‌شود: کاربر لینک پلیر وب با زیرنویس روشن/خاموش، لینک ویدیوی اصلی و SRT می‌گیرد. واترمارک یا ارسال مستقیم دوبله به تلگرام همچنان ممکن است به پردازش ویدیو نیاز داشته باشد.

## اجرا با Docker

1. ربات تلگرام را با BotFather بساز و API key سرویس OpenAI را آماده کن.
2. شناسهٔ عددی تلگرام مدیر را در `ALLOWED_USER_IDS` و `PROVIDER_CONTROL_USER_ID` بگذار. این شناسه برای پنل مدیریت و تغییر پردازشگر است؛ مشتریان عمومی به whitelist نیاز ندارند.
3. فایل نمونه را کپی و مقادیرش را کامل کن:

   ```sh
   cp .env.example .env
   ```

   برای PostgreSQL یک گذرواژهٔ تصادفی hex بساز و در `POSTGRES_PASSWORD` بگذار:

   ```sh
   openssl rand -hex 32
   ```

   این مقدار را در فایل `.env` نگه دار و در پیام یا Git قرار نده.

4. سرویس را بساز و اجرا کن:

   ```sh
   docker compose up --build -d
   docker compose logs -f bot
   ```

برای لینک مستقیم ویدیوهای بزرگ، `DOWNLOAD_BASE_URL` را در `.env` به دامنهٔ دانلود تنظیم کن، مثلاً `https://downloads.example.com`. رکورد DNS دامنه باید به IP سرور اشاره کند. Nginx داخل Compose فایل‌ها را روی `127.0.0.1:8080` سرو می‌کند؛ نمونهٔ تنظیم Nginx روی host در `deploy/nginx-host-vhost.conf.example` است. آن را با دامنهٔ خودت تنظیم کن، فعال کن و `nginx -t && systemctl reload nginx` اجرا کن. برای HTTPS، Certbot را برای همان دامنه فعال کن. اگر `.env` قبلاً از نمونهٔ قدیمی ساخته شده، `MAX_FILE_BYTES` را هم به `1000000000` تغییر بده تا دانلود ورودی پیش از ساخت لینک به سقف ۴۸ مگابایت محدود نشود.

5. برای توقف:

   ```sh
   docker compose down
   ```

فایل `.env` محرمانه است و داخل Git ثبت نمی‌شود. PostgreSQL فقط روی شبکهٔ خصوصی Docker در دسترس است و داده‌هایش در volume پایدار `postgres-data` می‌ماند. جدول‌های کاربران، jobها و لینک‌های دانلود در شروع برنامه ساخته می‌شوند. فایل‌های موقت هر job پس از ارسال یا خطا پاک می‌شوند؛ ویدیوهای منتشرشده نیز طبق TTL حذف می‌شوند.

| `ALLOWED_USER_IDS` | شناسهٔ مدیر ربات؛ مشتریان عمومی در این فهرست نیستند | اجباری |

| `TTS_VOICE` | صدای دوبلهٔ AI | `marin` |

مدل پیش‌فرض رونویسی مستقیم OpenAI یعنی `whisper-1` طبق اعلام OpenAI در ۲۶ فوریهٔ ۲۰۲۷ از دسترس خارج می‌شود؛ پیش از آن باید مسیر رونویسی زمان‌دار با مدل جایگزین به‌روزرسانی و آزمایش شود.

برای استفاده از OpenRouter، کلید آن را در `OPENROUTER_API_KEY` بگذار. ربات با `/provider` بین OpenAI و OpenRouter جابه‌جا می‌شود؛ فقط شناسهٔ `PROVIDER_CONTROL_USER_ID` اجازهٔ تغییر دارد و انتخاب در دیتابیس ذخیره می‌شود. OpenRouter برای ترجمه، Whisper timestampدار و TTS دوبله استفاده می‌شود. برای OpenAI، کلید `OPENAI_API_KEY` همچنان لازم است. `/limits` فقط سهمیهٔ OpenAI را می‌خواند؛ OpenRouter را از Activity آن سرویس بررسی کن.

منوی اصلی دکمه‌های سفارش جدید، وضعیت سفارش، کیف پول، تعرفه، گردش حساب و پشتیبانی دارد. برای تماس با پشتیبانی می‌توان پیام را پس از انتخاب دکمهٔ پشتیبانی مستقیماً ارسال کرد. رنگ دکمه‌ها در برنامه‌های تلگرامی پشتیبان نمایش داده می‌شود.

پس از انتخاب نوع و کیفیت، خلاصهٔ سفارش شامل مدت قابل‌محاسبه، تعرفه، مبلغ و موجودی نمایش داده می‌شود؛ تنها با دکمهٔ تأیید هزینه کم می‌شود. در همان مراحل دکمهٔ لغو وجود دارد.

مشتری از منوی «کیف پول ← شارژ کیف پول» مبلغ را مستقیماً می‌فرستد (دستور `/charge مبلغ` نیز فعال است) و درخواست کارت‌به‌کارت می‌سازد؛ سپس تصویر رسید یا شمارهٔ پیگیری را می‌فرستد. رسید در دیتابیس ثبت و برای مدیر فرستاده می‌شود؛ فقط با تأیید مدیر موجودی شارژ می‌شود. این اتصال، درگاه خودکار بانکی نیست و ربات گردش حساب را خودش استعلام نمی‌کند. مدیر با `/admin` نرخ‌ها و آمار را می‌بیند و از دکمه‌های شارژ/کسر کیف پول می‌تواند شناسهٔ تلگرام و مبلغ تومان را وارد کند. `/balance` موجودی و `/history` گردش حساب را نشان می‌دهند. هزینهٔ هر job بر اساس دقیقهٔ کامل رو به بالا محاسبه و پیش از دانلود به‌صورت اتمیک از کیف پول کم می‌شود. برای فروش عمومی، `CARD_TO_CARD_NUMBER` و `CARD_TO_CARD_HOLDER` و شناسهٔ مدیر را در `.env` سرور تنظیم کن؛ خریداران فقط در گفت‌وگوی خصوصی سفارش می‌سازند.

OpenRouter برای مدل‌های پولی سقف عمومی RPM تعیین نمی‌کند؛ محدودیت به provider مدل بستگی دارد. مدل‌های رایگان `:free` تا ۲۰ درخواست در دقیقه دارند (و سقف روزانهٔ حساب هم دارند). ربات برای درخواست‌های OpenRouter به‌طور پیش‌فرض با نرخ حداکثر ۱۰ RPM کار می‌کند، هدر `Retry-After` را رعایت می‌کند و 429/خطاهای موقت را تا ۸ بار به‌شکل افزایشی retry می‌کند. اگر Activity نشان داد provider انتخابی محدودیت پایین‌تری دارد، `OPENROUTER_RPM_LIMIT` را کمتر کن. برای دوبله، متن ترجمه‌شدهٔ هر حدود ۳۰ ثانیه در یک درخواست TTS ساخته می‌شود؛ ترجمهٔ کوتاه گفتاری هم از طول و هزینهٔ صدای تولیدی کم می‌کند.

برای بالا بردن limit، در OpenAI Platform به **Settings → Organization → Limits → Rate limits** برو و وضعیت سقف مدل را ببین. صفحهٔ Billing را هم بررسی کن؛ اضافه‌کردن روش پرداخت و ارتقای Usage Tier معمولاً سقف‌های بالاتری می‌دهد، اما مقدار دقیق را داشبورد برای سازمان/پروژه نشان می‌دهد. `/limits` سقف را فقط می‌خواند و تغییرش نمی‌دهد.

### وقتی یوتیوب درخواست ورود می‌کند

در صورت خطای `Sign in to confirm you're not a bot`، yt-dlp می‌تواند از فایل cookies استفاده کند. این فایل دسترسی حساب است: آن را در چت یا Git نفرست و فقط روی سرور با دسترسی محدود نگه دار. پوشهٔ `secrets/` به‌صورت فقط‌خواندنی به کانتینر وصل است و از Git و build context کنار گذاشته شده است.

1. یک فایل Netscape/Mozilla cookies مخصوص YouTube در `secrets/youtube-cookies.txt` قرار بده. از روش export مخصوص YouTube در مستندات yt-dlp استفاده کن؛ کل cookies همهٔ سایت‌های مرورگرت را export نکن.
2. در `.env` مقدار زیر را بگذار:

   ```dotenv
   YOUTUBE_COOKIES_FILE=/run/secrets/youtube-cookies.txt
   ```

3. کانتینر را recreate کن:

   ```sh
   docker compose up -d --force-recreate bot
   ```

Image از Deno و بستهٔ `yt-dlp-ejs` هم استفاده می‌کند؛ این‌ها برای حل challenge جاوااسکریپت YouTube لازم‌اند. بعد از تغییر Dockerfile یا requirements، حتماً با `--build` اجرا کن.

استفاده از cookies حساب اصلی ممکن است باعث محدودشدن حساب شود؛ فقط در صورت نیاز و با تعداد درخواست کم استفاده کن. Cookies باید با IP سروری که دانلود را انجام می‌دهد کار کند و ممکن است لازم باشد از مرورگری که از همان سرور به YouTube وصل می‌شود export شوند.

## رفتار فعلی

- صف درون‌حافظه‌ای با یک worker دارد؛ برای شروع فروش مناسب است اما در هر لحظه فقط یک job اجرا می‌شود. سفارش‌های پرداخت‌شده‌ای که هنگام restart نیمه‌تمام مانده باشند در شروع بعدی برای بازپرداخت فرستاده می‌شوند.
- PostgreSQL اطلاعات کاربر تلگرام، موجودی کیف پول، دفتر تراکنش تغییرناپذیر، درخواست‌های شارژ و رسیدها، نرخ‌های پنل، jobها، متن SRT و لینک‌های دانلود را نگه می‌دارد. مقادیر API key و cookies در دیتابیس ذخیره نمی‌شوند. فایل موقت job پس از ارسال یا خطا پاک می‌شود؛ ویدیوهای حجیم تا TTL در volume می‌مانند.
- jobهایی که هنگام restart در صف یا در حال اجرا بوده‌اند با وضعیت `interrupted` ثبت می‌شوند و مبلغشان به‌طور اتمیک به کیف پول برمی‌گردد؛ job به‌صورت خودکار از ابتدا اجرا نمی‌شود.
- دیتابیس پورت عمومی ندارد و فقط ربات به آن دسترسی شبکه‌ای دارد.
- فقط لینک‌های `youtube.com` و `youtu.be` پذیرفته می‌شوند؛ سرویس عمومی است و خرید فقط در گفت‌وگوی خصوصی انجام می‌شود. شناسهٔ مدیر را در `ALLOWED_USER_IDS` و `PROVIDER_CONTROL_USER_ID` قرار بده؛ این شناسه whitelist مشتریان نیست.
- صدا به تکه‌های ۸ دقیقه‌ای تقسیم می‌شود و timestamp هر تکه به زمان کلی ویدیو تبدیل می‌شود.
- yt-dlp با PO Token provider، JavaScript runtime و cookies اختیاری اجرا می‌شود. اگر URL رسانه با 403 رد شود، یک بار مسیر `mweb` دارای PO Token امتحان می‌شود؛ در صورت تکرار 403 باید مدتی صبر کرد و محدودیت IP سرور یا provider را بررسی کرد.
- پیش از دانلود، yt-dlp سقف حجم `MAX_FILE_BYTES` را اعمال می‌کند. فرمت انتخابی ممکن است در fallback از ارتفاع تنظیم‌شده بیشتر شود.
- زیرنویس بدون واترمارک و با دامنهٔ دانلود همیشه از صفحهٔ پلیر Nginx تحویل می‌شود، مستقل از حجم فایل. دوبله و خروجی‌های واترمارک‌دار تا ۴۸ مگابایت مستقیماً در تلگرام فرستاده می‌شوند؛ فایل‌های بزرگ‌تر از Nginx لینک می‌گیرند. فایل‌های منتشرشده پس از `DOWNLOAD_TTL_HOURS` پاک می‌شوند.
- وقتی `WATERMARK_TEXT` خالی است و `DOWNLOAD_BASE_URL` تنظیم شده، ویدیوی اصلی بدون رندر مجدد منتشر می‌شود. لینک توکنی صفحهٔ پخش وب، فایل SRT و دکمهٔ دانلود MP4 را می‌دهد؛ زیرنویس فارسی به صورت WebVTT با گزینهٔ روشن/خاموش در کنترل CC پلیر مرورگر نمایش داده می‌شود. برای پخش زیرنویس‌دار، کاربر لینک صفحهٔ پخش را باز می‌کند؛ فایل SRT نیز جداگانه در تلگرام فرستاده می‌شود.
- `/cancel` لغو را درخواست می‌کند؛ عملیات در حال اجرای yt-dlp یا درخواست API تا پایان گام جاری متوقف نمی‌شود. بین درخواست‌های ترجمه و تولید صدا نیز لغو بررسی می‌شود.
- اگر صدای ساخته‌شده در بازهٔ زمانی خود جا نشود، سفارش ناموفق می‌شود و مبلغ آن برگشت داده می‌شود؛ کوتاه‌کردن گفتار یا هم‌پوشانی صدا برای تحویل اجباری انجام نمی‌شود.
- هنگام پردازش، ربات در گفت‌وگوی خصوصی از live draft تلگرام برای نمایش نوار درصد و مرحله استفاده می‌کند؛ در چت‌هایی که این API را پشتیبانی نکنند پیام وضعیت معمولی و قابل ویرایش نشان داده می‌شود. متن پیشرفت فقط نام مرحله و درصد دارد و خطای داخلی یا مسیر فایل را نمایش نمی‌دهد.
- کاربر بین زیرنویس فارسی و دوبلهٔ فارسی انتخاب می‌کند. دوبله، صدای اصلی را با صدای فارسی تولیدشده توسط AI جایگزین می‌کند؛ پیام ویدیوی دوبله‌شده این موضوع را اعلام می‌کند.
- مقدار `WATERMARK_TEXT` در `.env` به صورت واترمارک در گوشهٔ بالا-چپ ویدیوهای زیرنویس و دوبله نمایش داده می‌شود؛ اگر خالی باشد واترمارک غیرفعال است. واترمارک و زیرنویس چسبیده encode مجدد می‌خواهند؛ برای کمترین پردازش، واترمارک را خالی بگذار تا زیرنویس به صورت ترک وب جدا نمایش داده شود.
- درخواست‌های صوتی Realtime برای هر خط جدا هستند؛ خطای موقت `rate_limit_exceeded` با مکث افزایشی تا چهار بار تلاش مجدد می‌شود. اگر محدودیت پایدار باشد، باید نرخ/سقف پروژهٔ OpenAI بررسی شود.
- پیش از دانلود فایل ویدیو، Admin API سقف پروژه و مصرف گزارش‌شدهٔ ۲۴ ساعت اخیر مدل‌های لازم برای حالت انتخاب‌شده را بررسی می‌کند؛ اگر سهمیهٔ روزانهٔ یکی از آن‌ها صفر باشد job شروع نمی‌شود. `/limits` همین اطلاعات را در تلگرام نشان می‌دهد. این پیش‌بررسی فقط وقتی فعال است که `OPENAI_ADMIN_KEY` و `OPENAI_PROJECT_ID` تنظیم باشند. دوبله برای هر بخش متن یک درخواست Realtime می‌فرستد و سقف‌های پایین RPD ممکن است برای کل ویدیو کافی نباشند.
- در پایان کار، پیام هزینهٔ تخمینی API را به USD نشان می‌دهد. رونویسی بر اساس مدت فایل، ترجمه بر اساس usage مدل و دوبله بر اساس usage توکنی Realtime محاسبه می‌شوند. برای مدل‌های ناشناخته در جدول قیمت داخلی، هزینهٔ ترجمه نامشخص گزارش می‌شود.
- لینک دانلود یک توکن تصادفی دارد و مثل لینک دارای دسترسی تلقی می‌شود؛ آن را فقط با دریافت‌کنندهٔ موردنظر به اشتراک بگذار.
- فایل‌های منتشرشده از Nginx کانتینری سرو می‌شوند؛ پلیر وب، ویدیو را با byte ranges پخش می‌کند و ترک WebVTT را از همان دامنه می‌خواند. صفحه، ویدیوی MP4 و فایل SRT را هم برای دانلود می‌دهد. درخواست‌های HTTP فقط `GET` و `HEAD` روی مسیرهای توکنی تصادفی پذیرفته می‌شوند؛ فهرست فایل‌ها و سایر مسیرها بسته‌اند.
- برای URL دامنه‌دار و HTTPS، DNS و reverse proxy میزبان را طبق نمونهٔ `deploy/nginx-host-vhost.conf.example` تنظیم کن. اگر از قبل Nginx میزبان را فعال کرده‌ای، تنظیم را با `nginx -t` بررسی و reload کن.
- این نسخه هنوز زیرنویس موجود یوتیوب را استخراج و ترجمه نمی‌کند.
- برای timestamp زیرنویس، فعلاً از `whisper-1` استفاده می‌شود؛ مستندات OpenAI زمان خاموشی API آن را ۲۶ فوریهٔ ۲۰۲۷ اعلام کرده‌اند. انتقال به رونویسی جدید نیازمند جایگزینی روش timestamp است.

## اجرای محلی بدون Docker

Python 3.12، `ffmpeg` با پشتیبانی libass، فونت Vazirmatn و یک PostgreSQL در دسترس لازم است. در این حالت `DATABASE_URL` را نیز در `.env` به شکل `postgresql+asyncpg://...` تنظیم کن:

```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.bot
```

## پشتیبان‌گیری PostgreSQL

```sh
docker compose exec -T database pg_dump -U ytbot ytbot > ytbot-backup.sql
```

برای بازیابی در دیتابیس خالی:

```sh
cat ytbot-backup.sql | docker compose exec -T database psql -U ytbot -d ytbot
```
