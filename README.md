# ربات تجاری تلگرام برای زیرنویس و دوبله فارسی یوتیوب

ربات عمومی لینک یوتیوب را می‌گیرد، نوع خروجی و کیفیت را می‌پرسد و هزینهٔ دقیقه‌ای را از کیف پول تومانی کم می‌کند. شارژ با کارت‌به‌کارت و بررسی دستی رسید انجام می‌شود؛ مدیر هم می‌تواند مستقیماً کاربران را شارژ یا از موجودی‌شان کم کند. نرخ‌ها از پنل `/admin` قابل تغییرند. job ناموفق یا نیمه‌تمام پس از restart به کیف پول برمی‌گردد. پیشرفت با پیام زنده و قابل‌ویرایش تلگرام نشان داده می‌شود. در حالت زیرنویس و بدون واترمارک، ویدیو re-encode نمی‌شود: کاربر لینک پلیر وب با زیرنویس روشن/خاموش، لینک ویدیوی اصلی و SRT می‌گیرد. واترمارک یا ارسال مستقیم دوبله به تلگرام همچنان ممکن است به پردازش ویدیو نیاز داشته باشد.

## گراف کد برای توسعه‌دهندگان

Graphify در محیط مستقل `.venv-graphify` نصب می‌شود و روی وابستگی‌ها یا اجرای ربات اثر ندارد. برای راه‌اندازی روی یک checkout جدید، با Python 3.10 یا جدیدتر اجرا کن:

```sh
python3 -m venv .venv-graphify
.venv-graphify/bin/python -m pip install 'graphifyy==0.9.71'
.venv-graphify/bin/graphify extract . --code-only
```

پیش از ویرایش کد، عامل با `.venv-graphify/bin/graphify query "<پرسش>"` بخش‌های مرتبط، فراخوانی‌ها و وابستگی‌ها را بررسی می‌کند؛ برای رابطهٔ مشخص می‌تواند از `path` یا `explain` استفاده کند. سپس فایل‌های مربوط را می‌خواند و نتیجهٔ گراف را با کد واقعی تطبیق می‌دهد. اگر گراف در دسترس نباشد، قدیمی یا ناقص باشد، از جست‌وجوی معمول و بررسی کد استفاده می‌کند.

پس از تغییرات اصلی کد از `.venv-graphify/bin/graphify update .` استفاده کن. این دستور گراف کد را محلی و بدون هزینهٔ API به‌روزرسانی می‌کند؛ محتوای مستندات به تحلیل معنایی جداگانه نیاز دارد. فایل‌های محرمانه، داده‌ها و محیط‌های مجازی با `.graphifyignore` کنار گذاشته شده‌اند. گراف فقط ابزاری برای راهبری است و جای بررسی فایل‌های واقعی را نمی‌گیرد؛ میزان صرفه‌جویی توکن به نوع کار بستگی دارد.

مهارت محلی Graphify در `.agents/skills/graphify` ثبت شده است. برای اجرای فرمان‌های آن با نام کوتاه `graphify` در ریشهٔ پروژه، ابتدا `export PATH="$PWD/.venv-graphify/bin:$PATH"` را در همان ترمینال اجرا کن. فایل‌های اصلی گراف قابل اشتراک‌اند؛ cache و نسخه‌های پشتیبان تولیدشده وارد Git نمی‌شوند.

## اجرا با Docker

1. ربات تلگرام را با BotFather بساز و API key سرویس OpenAI را آماده کن.
2. شناسهٔ عددی تلگرام مدیر را در `ALLOWED_USER_IDS` و `PROVIDER_CONTROL_USER_ID` بگذار. این شناسه برای پنل مدیریت و تغییر پردازشگر است؛ مشتریان عمومی به whitelist نیاز ندارند.
3. فایل نمونه را کپی و مقادیرش را کامل کن:

   ```sh
   cp .env.example .env
   ```

   برای PostgreSQL یک گذرواژهٔ تصادفی hex بساز و در `POSTGRES_PASSWORD` بگذار:

   ```sh
   openssl rand -hex 32
   ```

   این مقدار را در فایل `.env` نگه دار و در پیام یا Git قرار نده.

4. سرویس را بساز و اجرا کن:

   ```sh
   docker compose up --build -d
   docker compose logs -f bot
   ```

برای لینک دانلود HTTPS می‌توان به‌جای Nginx میزبان از Caddy داخل Docker استفاده کرد. Caddy گواهی را خودکار دریافت و تمدید می‌کند و به Nginx کانتینری پروژه وصل می‌شود. مراحل انتقال، بررسی پورت‌ها و بازگشت در بخش «HTTPS داخل Docker» پایین آمده‌اند. اگر `.env` قدیمی است، `MAX_FILE_BYTES=1000000000` را نیز بررسی کن. اجرای `docker compose up -d --build` به‌تنهایی همچنان از روش قبلی Nginx میزبان استفاده می‌کند؛ برای فعال‌کردن Caddy باید فایل Compose دوم را مطابق راهنما اضافه کنی.

5. برای توقف:

   ```sh
   docker compose down
   ```

   اگر Caddy را با فایل اختیاری HTTPS فعال کرده‌ای، برای توقف کامل به‌جای دستور بالا از `docker compose -f docker-compose.yml -f docker-compose.https.yml down` استفاده کن.

فایل `.env` محرمانه است و داخل Git ثبت نمی‌شود. PostgreSQL فقط روی شبکهٔ خصوصی Docker در دسترس است و داده‌هایش در volume پایدار `postgres-data` می‌ماند. جدول‌های کاربران، jobها و لینک‌های دانلود در شروع برنامه ساخته می‌شوند. فایل‌های موقت هر job پس از ارسال یا خطا پاک می‌شوند؛ ویدیوهای منتشرشده نیز طبق TTL حذف می‌شوند.

### مدل‌ها و صدای دوبله در پنل مدیر

در `/admin` دکمهٔ «مدل‌ها و صدای دوبله» را انتخاب کن. مدل رونویسی، ترجمه و تولید صدا برای پردازشگر فعلی انتخاب می‌شوند و تنظیمات هر پردازشگر جدا ذخیره می‌شود؛ فهرست گوینده‌ها بر اساس سرویس مدل دوبله است. برای هر مدل، نرخ راهنمای دلاری در پنل نمایش داده می‌شود. برای Gemini هزینهٔ خروجی به‌طور تقریبی بر اساس ۲۵ توکن صوتی در ثانیه به دقیقه تبدیل می‌شود؛ هزینهٔ متن ورودی و تکرار تولید جداست. هزینهٔ دقیقه‌ای OpenAI بدون نرخ تبدیل تأییدشده نامشخص است. سایر نرخ‌های توکنی به ازای یک میلیون توکن هستند و قیمت‌ها ثابت یا تضمین‌شده نیستند؛ قیمت نهایی، دسترسی حساب و سازگاری را در سرویس مربوط بررسی کن. انتخاب‌ها در دیتابیس ذخیره و هنگام تأیید سفارش برای همان سفارش ثابت می‌شوند. کلید هر سرویس انتخاب‌شده باید در `.env` موجود باشد؛ پیش از کسر هزینه کنترل می‌شود. تنظیمات `.env` برای مراحلی به کار می‌روند که برای پردازشگر فعلی در پنل انتخاب نشده‌اند.

شدت صدای اصلی هنگام دوبله از دکمهٔ «صدای اصلی دوبله» در `/admin` انتخاب می‌شود. مقدار پیش‌فرض ۱۰٪ است و مدیر می‌تواند عددی از ۰ تا ۱۰۰٪ تعیین کند؛ این تنظیم روی سفارش‌های دوبلهٔ بعدی اعمال می‌شود.

در صفحهٔ مدل‌های پردازش، برآورد دلار به ازای هر دقیقه برای هر مرحله و جمع جداگانهٔ زیرنویس و دوبله نمایش داده می‌شود. سناریوی نمونه برای هر دقیقه ویدیو ۶۰ ثانیه رونویسی، ۳۰۰ توکن ورودی و ۱۵۰ توکن خروجی ترجمه و برای دوبله ۶۰ ثانیه صوت خروجی و ۳۰۰ توکن ورودی صدا فرض می‌کند. هزینهٔ بازنویسی و تلاش مجدد را شامل نمی‌شود؛ مقادیر فرضی تضمین مصرف نیستند. اگر نرخ مدل ناشناخته باشد جمع نیز نامشخص می‌ماند.

گزینه‌های فهرست‌شده با قالب‌های فعلی برنامه انتخاب شده‌اند؛ پیش از فروش با هر مدل و صدای جدید یک ویدیوی نمونه را آزمایش کن. قیمت‌های داخل فهرست دستی و مربوط به ۱۲ نوامبر ۲۰۲۶ هستند. هزینهٔ گزارش‌شدهٔ هر سفارش در صورت نامشخص بودن مصرف هر مرحله «نامشخص» است. `/limits` همچنان فقط مدل‌های OpenAI تنظیم‌شده در `.env` را بررسی می‌کند.

برای استفاده از OpenRouter، کلید آن را در `OPENROUTER_API_KEY` بگذار. ربات با `/provider` پردازشگر تمام مراحل سفارش‌های بعدی را تغییر می‌دهد؛ فقط شناسهٔ `PROVIDER_CONTROL_USER_ID` اجازهٔ تغییر دارد و انتخاب در دیتابیس ذخیره می‌شود. برای هر مرحله‌ای که OpenAI برای آن انتخاب شود، کلید `OPENAI_API_KEY` لازم است. `/limits` فقط سهمیهٔ OpenAI را می‌خواند؛ OpenRouter را از Activity آن سرویس بررسی کن.

منوی اصلی دکمه‌های سفارش جدید، سفارش‌های من، کیف پول، تعرفه، گردش حساب و پشتیبانی دارد. در «سفارش‌های من» کاربر سفارش‌های زیرنویس و دوبلهٔ خود را به‌صورت صفحه‌بندی‌شده می‌بیند. لینک‌های دانلود فقط تا زمان انقضا و تا وقتی فایل روی سرور وجود دارد نمایش داده می‌شوند؛ فایل‌هایی که مستقیم در تلگرام ارسال شده‌اند لزوماً لینک دانلود ندارند. برای تماس با پشتیبانی می‌توان پیام را پس از انتخاب دکمهٔ پشتیبانی مستقیماً ارسال کرد. رنگ دکمه‌ها در برنامه‌های تلگرامی پشتیبان نمایش داده می‌شود.

برای سفارش ویدیو، وضعیت مرحله و درصد تقریبی در پیام سفارش و، در چت خصوصی پشتیبانی‌شده، به شکل پیش‌نویس زندهٔ تلگرام نمایش داده می‌شود. اگر پیش‌نویس در دسترس نباشد پیام سفارش به‌روزرسانی می‌شود. از منوی اصلی می‌توان وضعیت و درخواست لغو همان سفارش را دید؛ لغو پس از پایان مرحلهٔ جاری انجام می‌شود و با شروع تحویل دیگر ممکن نیست. درصد تخمین مراحل است و زمان باقی‌مانده یا درصد واقعی کل کار محسوب نمی‌شود.

پس از انتخاب نوع و کیفیت، خلاصهٔ سفارش شامل مدت قابل‌محاسبه، تعرفه، مبلغ و موجودی نمایش داده می‌شود؛ تنها با دکمهٔ تأیید هزینه کم می‌شود. در همان مراحل دکمهٔ لغو وجود دارد.

مشتری از منوی «کیف پول ← شارژ کیف پول» مبلغ را مستقیماً می‌فرستد (دستور `/charge مبلغ` نیز فعال است) و درخواست کارت‌به‌کارت می‌سازد؛ سپس تصویر رسید یا شمارهٔ پیگیری را می‌فرستد. رسید در دیتابیس ثبت و برای مدیر فرستاده می‌شود؛ فقط با تأیید مدیر موجودی شارژ می‌شود. این اتصال، درگاه خودکار بانکی نیست و ربات گردش حساب را خودش استعلام نمی‌کند. مدیر با `/admin` نرخ‌ها و آمار را می‌بیند و از دکمه‌های شارژ/کسر کیف پول می‌تواند شناسهٔ تلگرام و مبلغ تومان را وارد کند. `/balance` موجودی و `/history` گردش حساب را نشان می‌دهند. هزینهٔ هر job بر اساس دقیقهٔ کامل رو به بالا محاسبه و پیش از دانلود به‌صورت اتمیک از کیف پول کم می‌شود. برای فروش عمومی، `CARD_TO_CARD_NUMBER` و `CARD_TO_CARD_HOLDER` و شناسهٔ مدیر را در `.env` سرور تنظیم کن؛ خریداران فقط در گفت‌وگوی خصوصی سفارش می‌سازند.

OpenRouter برای مدل‌های پولی سقف عمومی RPM تعیین نمی‌کند؛ محدودیت به provider مدل بستگی دارد. مدل‌های رایگان `:free` تا ۲۰ درخواست در دقیقه دارند (و سقف روزانهٔ حساب هم دارند). ربات برای درخواست‌های OpenRouter به‌طور پیش‌فرض با نرخ حداکثر ۱۰ RPM کار می‌کند، هدر `Retry-After` را رعایت می‌کند و 429/خطاهای موقت را تا ۸ بار به‌شکل افزایشی retry می‌کند. اگر Activity نشان داد provider انتخابی محدودیت پایین‌تری دارد، `OPENROUTER_RPM_LIMIT` را کمتر کن. برای دوبله، متن ترجمه‌شدهٔ هر حدود ۳۰ ثانیه در یک درخواست TTS ساخته می‌شود؛ ترجمهٔ کوتاه گفتاری هم از طول و هزینهٔ صدای تولیدی کم می‌کند.

برای بالا بردن limit، در OpenAI Platform به **Settings → Organization → Limits → Rate limits** برو و وضعیت سقف مدل را ببین. صفحهٔ Billing را هم بررسی کن؛ اضافه‌کردن روش پرداخت و ارتقای Usage Tier معمولاً سقف‌های بالاتری می‌دهد، اما مقدار دقیق را داشبورد برای سازمان/پروژه نشان می‌دهد. `/limits` سقف را فقط می‌خواند و تغییرش نمی‌دهد.

### وقتی یوتیوب درخواست ورود می‌کند

در صورت خطای `Sign in to confirm you're not a bot`، yt-dlp می‌تواند از فایل cookies استفاده کند. این فایل دسترسی حساب است: آن را در چت یا Git نفرست و فقط روی سرور با دسترسی محدود نگه دار. پوشهٔ `secrets/` به‌صورت فقط‌خواندنی به کانتینر وصل است و از Git و build context کنار گذاشته شده است.

1. یک فایل Netscape/Mozilla cookies مخصوص YouTube در `secrets/youtube-cookies.txt` قرار بده. از روش export مخصوص YouTube در مستندات yt-dlp استفاده کن؛ کل cookies همهٔ سایت‌های مرورگرت را export نکن.
2. در `.env` مقدار زیر را بگذار:

   ```dotenv
   YOUTUBE_COOKIES_FILE=/run/secrets/youtube-cookies.txt
   ```

3. کانتینر را recreate کن:

   ```sh
   docker compose up -d --force-recreate bot
   ```

Image از Deno و بستهٔ `yt-dlp-ejs` هم استفاده می‌کند؛ این‌ها برای حل challenge جاوااسکریپت YouTube لازم‌اند. بعد از تغییر Dockerfile یا requirements، حتماً با `--build` اجرا کن.

استفاده از cookies حساب اصلی ممکن است باعث محدودشدن حساب شود؛ فقط در صورت نیاز و با تعداد درخواست کم استفاده کن. Cookies باید با IP سروری که دانلود را انجام می‌دهد کار کند و ممکن است لازم باشد از مرورگری که از همان سرور به YouTube وصل می‌شود export شوند.

## رفتار فعلی

- صف درون‌حافظه‌ای با یک worker دارد؛ برای شروع فروش مناسب است اما در هر لحظه فقط یک job اجرا می‌شود. سفارش‌های پرداخت‌شده‌ای که هنگام restart نیمه‌تمام مانده باشند در شروع بعدی برای بازپرداخت فرستاده می‌شوند.
- PostgreSQL اطلاعات کاربر تلگرام، موجودی کیف پول، دفتر تراکنش تغییرناپذیر، درخواست‌های شارژ و رسیدها، نرخ‌های پنل، jobها، متن SRT و لینک‌های دانلود را نگه می‌دارد. مقادیر API key و cookies در دیتابیس ذخیره نمی‌شوند. فایل موقت job پس از ارسال یا خطا پاک می‌شود؛ ویدیوهای حجیم تا TTL در volume می‌مانند.
- jobهایی که هنگام restart در صف یا در حال اجرا بوده‌اند با وضعیت `interrupted` ثبت می‌شوند و مبلغشان به‌طور اتمیک به کیف پول برمی‌گردد؛ job به‌صورت خودکار از ابتدا اجرا نمی‌شود.
- دیتابیس پورت عمومی ندارد و فقط ربات به آن دسترسی شبکه‌ای دارد.
- گزینهٔ «زیرنویس ویدیوی ارسالی» ویدیوی تلگرامی تا ۲۰ مگابایت و ۹۰ ثانیه را می‌پذیرد، از تعرفهٔ دقیقه‌ای زیرنویس کیف پول یا بستهٔ زیرنویس استفاده می‌کند و در صورت شکست هزینه یا دقیقه‌ها را برمی‌گرداند. تشخیص گفتار محلی است و مدل باید پیشاپیش نصب شود؛ زبان گفتار، رنگ و فونت زیرنویس بعد از ارسال ویدیو انتخاب می‌شوند.
- برای لینک پست، ریلز، استوری یا هایلایت Instagram یک گزینهٔ «دانلود هوشمند» نمایش داده می‌شود. ربات خودش نوع عکس، ویدیو یا کاروسل ترکیبی را تشخیص می‌دهد؛ عکس‌های تکی به‌صورت عکس تلگرامی و چند مدیا در ZIP ارسال می‌شوند. بالاترین وضوح موجود از Instagram انتخاب می‌شود. برای لینک مستقیم پروفایل نیز گزینهٔ جداگانهٔ دانلود عکس پروفایل با وضوح HD موجود است. Story، Highlight و پروفایل‌های خصوصی به نشست معتبر نیاز دارند و ممکن است با تغییرات Instagram یا محدودیت دسترسی از کار بیفتند. محتوای خصوصی، حذف‌شده یا منقضی‌شده قابل‌بازیابی نیست.
- سرویس عمومی است و خرید فقط در گفت‌وگوی خصوصی انجام می‌شود. شناسهٔ مدیر را در `ALLOWED_USER_IDS` و `PROVIDER_CONTROL_USER_ID` قرار بده؛ این شناسه whitelist مشتریان نیست.
- صدا به تکه‌های حدود ۸ دقیقه‌ای تقسیم می‌شود؛ timestamp هر تکه با زمان شروع واقعی ثبت‌شده توسط FFmpeg به زمان کلی ویدیو تبدیل می‌شود.
- ترجمه با توجه به موضوع، لحن و زمینهٔ بخش‌های مجاور انجام می‌شود و برای هر قطعه یک ترجمه در بازهٔ خودش نگه می‌دارد؛ زمینهٔ اضافی می‌تواند مصرف توکن را کمی افزایش دهد.
- برای زیرنویس، زمان کلمه‌ها از مدل‌های سازگار درخواست می‌شود و گفتار به بخش‌های کوتاه‌تر ترجمه می‌شود. زیرنویس فارسی در SRT، VTT و نسخهٔ چسبیده با حداکثر دو خط معمول و بدون هم‌پوشانی ساخته می‌شود. اگر زمان برخی کلمات ناقص باشد، زمان دقیق بخش‌های کامل حفظ و فقط بخش‌های فاقد زمان کافی به‌صورت تخمینی تقسیم می‌شوند؛ هم‌زمانی کلمه‌به‌کلمه یا تشخیص هویت گویندگان تضمین نمی‌شود. خروجی‌های قبلی خودکار تغییر نمی‌کنند.
- yt-dlp با PO Token provider، JavaScript runtime و cookies اختیاری اجرا می‌شود. اگر URL رسانه با 403 رد شود، یک بار مسیر `mweb` دارای PO Token امتحان می‌شود؛ در صورت تکرار 403 باید مدتی صبر کرد و محدودیت IP سرور یا provider را بررسی کرد.
- پیش از دانلود، yt-dlp سقف حجم `MAX_FILE_BYTES` را اعمال می‌کند. فرمت انتخابی ممکن است در fallback از ارتفاع تنظیم‌شده بیشتر شود.
- زیرنویس بدون واترمارک و با دامنهٔ دانلود همیشه از صفحهٔ پلیر Nginx تحویل می‌شود، مستقل از حجم فایل. دوبله و خروجی‌های واترمارک‌دار تا ۴۸ مگابایت مستقیماً در تلگرام فرستاده می‌شوند؛ فایل‌های بزرگ‌تر از Nginx لینک می‌گیرند. فایل‌های منتشرشده پس از `DOWNLOAD_TTL_HOURS` پاک می‌شوند.
- وقتی `WATERMARK_TEXT` خالی است و `DOWNLOAD_BASE_URL` تنظیم شده، ویدیوی اصلی بدون رندر مجدد منتشر می‌شود. لینک توکنی صفحهٔ پخش وب، فایل SRT و دکمهٔ دانلود MP4 را می‌دهد؛ زیرنویس فارسی به صورت WebVTT با گزینهٔ روشن/خاموش در کنترل CC پلیر مرورگر نمایش داده می‌شود. برای پخش زیرنویس‌دار، کاربر لینک صفحهٔ پخش را باز می‌کند؛ فایل SRT نیز جداگانه در تلگرام فرستاده می‌شود.
- `/cancel` لغو را درخواست می‌کند؛ عملیات در حال اجرای yt-dlp یا درخواست API تا پایان گام جاری متوقف نمی‌شود. بین درخواست‌های ترجمه و تولید صدا نیز لغو بررسی می‌شود.
- اگر صدای دوبله در بازهٔ زمانی خود جا نشود، متن همان بخش تا دو بار بازنویسی و صدا دوباره ساخته می‌شود؛ اگر بازنویسی کوتاه‌تر نشود، تولید مجدد همچنان امتحان می‌شود. در آخرین راهکار، سریع‌ترین صدای کامل تا سقف ۱٫۸ برابر پخش می‌شود؛ در صورت جا نشدن، سفارش ناموفق و مبلغ برگشت داده می‌شود. صدای سریع‌تر ممکن است طبیعی نباشد؛ بازنویسی و تلاش مجدد نیز می‌تواند هزینهٔ API را افزایش دهد و ممکن است جزئیاتی را حذف کند.
- هنگام پردازش، ربات در گفت‌وگوی خصوصی از live draft تلگرام برای نمایش نوار درصد و مرحله استفاده می‌کند؛ در چت‌هایی که این API را پشتیبانی نکنند پیام وضعیت معمولی و قابل ویرایش نشان داده می‌شود. متن پیشرفت فقط نام مرحله و درصد دارد و خطای داخلی یا مسیر فایل را نمایش نمی‌دهد.
- کاربر هنگام دوبله بین «ساده» و «هوشمند» انتخاب می‌کند. روش ساده صدای اصلی را هنگام گفتار فارسی کاهش می‌دهد و ممکن است دیالوگ اصلی شنیده شود. روش هوشمند با Spleeter روی CPU صدای پس‌زمینه را به‌طور تقریبی جدا می‌کند و سپس با دوبله میکس می‌کند؛ بسته به فایل ممکن است گفتار باقی بماند یا موسیقی و افکت‌ها آسیب ببینند. هر دو روش از یک گویندهٔ انتخاب‌شده در پنل استفاده می‌کنند و تشخیص شخصیت، بازیگری احساسی و هماهنگی لب خودکار ندارند.

سرویس دوبلهٔ هوشمند به‌صورت پیش‌فرض همراه Compose اجرا می‌شود؛ سرویس‌ها را با `docker compose up -d --build` اجرا کن (اگر از فایل HTTPS هم استفاده می‌کنی، همان گزینه‌های `-f` قبلی را نیز اضافه کن). مدل Spleeter در نخستین پردازش دانلود و در volume جداگانه ذخیره می‌شود؛ دسترسی اینترنت لازم است. پردازش روی ۴ vCPU می‌تواند بسیار کند باشد و فضای موقت قابل‌توجهی برای فایل‌های صوتی می‌خواهد. اگر سرویس فعال نباشد، پیش از تأیید سفارش اعلام می‌شود؛ خطای پردازش طبق سازوکار سفارش ناموفق بازپرداخت می‌شود. فعلاً تعرفهٔ هر دو روش یکسان است و باید ظرفیت CPU و هزینهٔ آن را در تعرفه لحاظ کنی.
- برای کنترل مصرف FFmpeg، مقدار `FFMPEG_THREADS` به‌صورت پیش‌فرض ۲ و `FFMPEG_PRESET` برابر `superfast` است. رشتهٔ کمتر ممکن است روی بعضی سیستم‌ها زمان پردازش را بیشتر کند؛ preset سریع‌تر ممکن است حجم خروجی را افزایش دهد. صدای AAC هنگام چسباندن زیرنویس بدون encode مجدد کپی می‌شود.
- مقدار `WATERMARK_TEXT` در `.env` به صورت واترمارک در گوشهٔ بالا-چپ ویدیوهای زیرنویس و دوبله نمایش داده می‌شود؛ اگر خالی باشد واترمارک غیرفعال است. واترمارک و زیرنویس چسبیده encode مجدد می‌خواهند؛ برای کمترین پردازش، واترمارک را خالی بگذار تا زیرنویس به صورت ترک وب جدا نمایش داده شود.
- درخواست‌های صوتی Realtime برای هر خط جدا هستند؛ خطای موقت `rate_limit_exceeded` با مکث افزایشی تا چهار بار تلاش مجدد می‌شود. اگر محدودیت پایدار باشد، باید نرخ/سقف پروژهٔ OpenAI بررسی شود.
- پیش از دانلود فایل ویدیو، Admin API سقف پروژه و مصرف گزارش‌شدهٔ ۲۴ ساعت اخیر مدل‌های لازم برای حالت انتخاب‌شده را بررسی می‌کند؛ اگر سهمیهٔ روزانهٔ یکی از آن‌ها صفر باشد job شروع نمی‌شود. `/limits` همین اطلاعات را در تلگرام نشان می‌دهد. این پیش‌بررسی فقط وقتی فعال است که `OPENAI_ADMIN_KEY` و `OPENAI_PROJECT_ID` تنظیم باشند. دوبله برای هر بخش متن یک درخواست Realtime می‌فرستد و سقف‌های پایین RPD ممکن است برای کل ویدیو کافی نباشند.
- در پایان کار، پیام هزینهٔ تخمینی API را به USD نشان می‌دهد. رونویسی بر اساس مدت فایل، ترجمه بر اساس usage مدل و دوبله بر اساس usage توکنی Realtime محاسبه می‌شوند. برای مدل‌های ناشناخته در جدول قیمت داخلی، هزینهٔ ترجمه نامشخص گزارش می‌شود.
- لینک دانلود یک توکن تصادفی دارد و مثل لینک دارای دسترسی تلقی می‌شود؛ آن را فقط با دریافت‌کنندهٔ موردنظر به اشتراک بگذار.
- فایل‌های منتشرشده از Nginx کانتینری سرو می‌شوند؛ پلیر وب، ویدیو را با byte ranges پخش می‌کند و ترک WebVTT را از همان دامنه می‌خواند. صفحه، ویدیوی MP4 و فایل SRT را هم برای دانلود می‌دهد. درخواست‌های HTTP فقط `GET` و `HEAD` روی مسیرهای توکنی تصادفی پذیرفته می‌شوند؛ فهرست فایل‌ها و سایر مسیرها بسته‌اند.
- برای HTTPS می‌توان از Nginx میزبان با نمونهٔ `deploy/nginx-host-vhost.conf.example` یا از Caddy کانتینری با فایل اختیاری `docker-compose.https.yml` استفاده کرد؛ هم‌زمان نمی‌توانند روی پورت‌های یکسان گوش بدهند.
- این نسخه هنوز زیرنویس موجود یوتیوب را استخراج و ترجمه نمی‌کند.
- برای timestamp زیرنویس، فعلاً از `whisper-1` استفاده می‌شود؛ مستندات OpenAI زمان خاموشی API آن را ۲۶ فوریهٔ ۲۰۲۷ اعلام کرده‌اند. انتقال به رونویسی جدید نیازمند جایگزینی روش timestamp است.

## اجرای محلی بدون Docker

Python 3.12، `ffmpeg` با پشتیبانی libass، فونت Vazirmatn و یک PostgreSQL در دسترس لازم است. در این حالت `DATABASE_URL` را نیز در `.env` به شکل `postgresql+asyncpg://...` تنظیم کن:

```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.bot
```

## پشتیبان‌گیری PostgreSQL

```sh
docker compose exec -T database pg_dump -U ytbot ytbot > ytbot-backup.sql
```

برای بازیابی در دیتابیس خالی:

```sh
cat ytbot-backup.sql | docker compose exec -T database psql -U ytbot -d ytbot
```

### زیرنویس انیمیشنی ویدیوی ارسالی

در Docker شش خانوادهٔ فونت Vazirmatn، Noto Sans Arabic، Noto Naskh Arabic، Noto Sans، Noto Serif و Montserrat به‌همراه اعلان‌های مجوزشان در `/app/assets/fonts` قرار می‌گیرند. کاربر هنگام سفارش زیرنویس، فونت و اندازهٔ کوچک، متوسط یا بزرگ را انتخاب می‌کند. ایمیج وجود پشتیبانی `ass`، HarfBuzz و چیدمان کامل متن در libass را بررسی می‌کند تا ترتیب راست‌به‌چپ فارسی بین رنگ‌آمیزی واژه‌ها حفظ شود. مدل faster-whisper باید یک بار با اتصال اینترنت روی volume پایدار دانلود شود؛ هنگام پردازش از مسیر محلی خوانده می‌شود و به API گفتار متصل نمی‌شود:

وابستگی‌های گفتار از `faster-whisper==1.2.1` و `av<19` استفاده می‌کنند؛ PyAV 19 پارامتری را که این نسخهٔ faster-whisper برای خواندن صوت نیاز دارد حذف کرده است. هنگام ساخت ایمیج یک نمونهٔ صوتی کوتاه با دیکودر واقعی بررسی می‌شود. پس از تغییر وابستگی‌ها ایمیج bot را دوباره بساز؛ مدل ذخیره‌شده در volume نیازی به دانلود مجدد ندارد.

```sh
docker compose build bot
docker compose run --rm --no-deps --entrypoint python bot -c 'from faster_whisper.utils import download_model; download_model("medium", output_dir="/data/models/whisper-medium")'
docker compose up -d bot
```

پیش‌فرض جدید مدل چندزبانهٔ `medium` است؛ برای نسخه‌های قبلی که `small` را نصب کرده‌اند باید دستور دانلود بالا یک بار اجرا شود. اگر سرور به اینترنت مدل دسترسی ندارد، پوشهٔ مدل CTranslate2 شامل `model.bin`، `config.json`، tokenizer و vocabulary را روی یک دستگاه متصل دانلود کن و به مسیر `/data/models/whisper-medium` در volume ربات منتقل کن. پردازش `medium` روی CPU حافظه و زمان بیشتری می‌خواهد؛ برای استفاده از مدل قبلی، `CAPTION_MODEL_PATH=/data/models/whisper-small` را در `.env` قرار بده. اگر این متغیر قبلاً در `.env` روی مسیر `small` تنظیم شده، برای استفاده از مدل جدید آن را به `/data/models/whisper-medium` تغییر بده. `CAPTION_FONTS_DIR` مسیر فونت‌هاست.

برای اجرای مستقیم روی Ubuntu، Python 3.12 و بسته‌های سیستمی را نصب کن:

```sh
sudo apt-get update
sudo apt-get install -y ffmpeg libass9 libharfbuzz0b fonts-vazirmatn fonts-montserrat fonts-noto-core libgl1 libglib2.0-0
python3 -m pip install -r requirements.txt
mkdir -p assets/fonts models/whisper-medium
cp "$(fc-match -f '%{file}' 'Vazirmatn:style=Bold')" assets/fonts/Vazirmatn-Bold.ttf
cp "$(fc-match -f '%{file}' 'Montserrat:style=ExtraBold')" assets/fonts/Montserrat-ExtraBold.ttf
cp "$(fc-match -f '%{file}' 'Noto Sans Arabic:style=Bold')" assets/fonts/NotoSansArabic-Bold.ttf
cp "$(fc-match -f '%{file}' 'Noto Naskh Arabic:style=Bold')" assets/fonts/NotoNaskhArabic-Bold.ttf
cp "$(fc-match -f '%{file}' 'Noto Sans:style=Bold')" assets/fonts/NotoSans-Bold.ttf
cp "$(fc-match -f '%{file}' 'Noto Serif:style=Bold')" assets/fonts/NotoSerif-Bold.ttf
python3 -c 'from faster_whisper.utils import download_model; download_model("medium", output_dir="models/whisper-medium")'
```

برای اجرای مستقیم، `CAPTION_MODEL_PATH` را به مسیر مطلق `models/whisper-medium` و `CAPTION_FONTS_DIR` را به مسیر مطلق `assets/fonts` در `.env` تنظیم کن. با `ffmpeg -filters | grep -E ' (ass|subtitles) '` وجود libass و با `ldd /usr/lib/x86_64-linux-gnu/libass.so.9 | grep harfbuzz` اتصال HarfBuzz را بررسی کن؛ در صورت نبودشان FFmpeg و libass توزیع را نصب یا با این قابلیت‌ها بازسازی کن.

برای بررسی دستی، ویدیوی کوتاه دارای گفتار فارسی یا انگلیسی را ارسال کن و گزینهٔ زیرنویس را انتخاب کن.

### HTTPS داخل Docker و انتقال از Nginx میزبان

این روش دامنهٔ دانلود را به Caddy کانتینری متصل می‌کند. صدور و تمدید گواهی خودکار است و گواهی‌ها در volume پایدار `caddy-data` ذخیره می‌شوند. فایل‌ها همچنان از Nginx کانتینری با همان محدودیت مسیرها سرو می‌شوند. **پیش از توقف Nginx میزبان، بررسی کن سایت یا سرویس دیگری به آن وابسته نباشد**؛ انتقال فقط پیکربندی این پروژه را شامل می‌شود.

۱. فایل `.env` سرور را ویرایش کن و هر دو مقدار را برای یک دامنه تنظیم کن؛ `DOWNLOAD_HOST` فقط نام دامنه است:

```dotenv
DOWNLOAD_HOST=downloads.example.com
DOWNLOAD_BASE_URL=https://downloads.example.com
```

۲. رکورد A دامنه را به IP عمومی سرور وصل کن. اگر رکورد AAAA داری، باید به IPv6 همین سرور اشاره کند و IPv6 نیز در دسترس باشد. پورت‌های TCP 80 و 443 را در فایروال سرور و فایروال ارائه‌دهنده باز کن. برای مثال، اگر UFW فعال است:

```sh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

۳. پورت‌ها و سایت‌های فعلی میزبان را بررسی کن:

```sh
sudo ss -ltnp | grep -E ':80 |:443 '
sudo nginx -T
```

۴. فقط اگر مطمئن هستی سایت دیگری به Nginx میزبان وابسته نیست، آن را متوقف و غیرفعال کن تا پورت‌ها آزاد شوند. این کار قابل برگشت است؛ در این مرحله فایل‌های تنظیمات و گواهی‌های میزبان را حذف نکن:

```sh
sudo systemctl disable --now nginx
sudo ss -ltnp | grep -E ':80 |:443 '
```

۵. در پوشهٔ پروژه Caddy را همراه بقیهٔ سرویس‌ها بالا بیاور و وضعیت صدور گواهی را بررسی کن:

```sh
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.https.yml logs -f caddy
```

اگر نسخهٔ قبلی Nginx کانتینری اجراست و تنظیمات آن تغییر کرده‌اند، `docker compose restart downloads-nginx` را هم اجرا کن. سپس در مرورگر یا با `curl -I https://downloads.example.com/` دامنه را بررسی کن؛ پاسخ `404` برای مسیر `/` طبیعی است، اما اتصال باید HTTPS معتبر داشته باشد. یک لینک دانلود واقعی را هم آزمایش کن. صدور گواهی به DNS و دسترسی عمومی پورت‌ها وابسته است؛ خروجی `logs` خطاهای آن را نشان می‌دهد.

برای اجرای مجدد، بررسی، یا توقف Caddy از هر دو فایل Compose استفاده کن؛ مثلاً:

```sh
docker compose -f docker-compose.yml -f docker-compose.https.yml ps
```

برای بازگشت به Nginx میزبان، ابتدا فقط Caddy را متوقف کن و سپس Nginx میزبان را مجدداً فعال کن؛ تنظیم قبلی باید هنوز موجود باشد:

```sh
docker compose -f docker-compose.yml -f docker-compose.https.yml stop caddy
sudo nginx -t
sudo systemctl enable --now nginx
```

پس از تأیید کارکرد و اطمینان از اینکه هیچ سایت دیگری به بستهٔ Nginx میزبان نیاز ندارد، حذف بسته اختیاری است: `sudo apt remove nginx`. از `purge` یا حذف `/etc/letsencrypt` استفاده نکن مگر مطمئن باشی تنظیمات و گواهی‌های میزبان دیگر لازم نیستند. Volumeهای Docker، به‌خصوص `caddy-data` و دیتابیس را با `docker compose down -v` حذف نکن.

### بسته‌های دقیقه

مدیر از `/admin` می‌تواند برای زیرنویس و دوبله بسته‌های دقیقه تنظیم کند. اعتبار و تراکنش‌های قبلی حفظ می‌شوند و پرداخت یا بازپرداخت سفارش‌ها مانند قبل انجام می‌شود.
